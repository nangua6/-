# 面试彩排稿

## 一、开场一分钟版本

面试官您好，这个项目是一个制造业企业 AI Agent 平台。它不是普通聊天机器人，而是把 LLM、业务数据库、企业知识库、工具调用和可观测系统组合在一起，让员工用自然语言查询库存、订单、生产进度、采购信息，并结合企业制度进行分析。项目里 LLM 只负责理解和决策，真实事实都来自数据库和知识库。

## 二、五分钟版本

这个项目分为五层：

1. 业务系统层：PostgreSQL 存储产品、库存、订单、生产、采购、客户数据。
2. Agent 层：接收用户问题后，先做上下文加载和 RAG 检索，再决定调用哪些工具。
3. Tool 层：所有工具都由后端执行，LLM 不允许编造业务数据。
4. RAG 层：支持文档上传、解析、分块、Embedding、检索、Rerank、引用溯源。
5. 可观测层：每次 Agent 请求都会记录 Trace、Tool、Token、Latency 和 Cost。

我做这个项目的目标不是“做一个能聊天的页面”，而是做一个能讲清 AI 系统边界的企业系统。

## 三、高频问题彩排

### 1. 为什么使用 Agent？
因为真实业务问题通常不是单查询。比如“SO20260001 为什么可能延期”，需要同时查订单、生产进度、库存，再结合规则判断风险。Agent 可以把这类任务拆成多步执行。

### 2. 为什么使用 Function Calling？
Function Calling 让模型输出结构化工具调用，而不是自由文本猜测。这样后端可以执行真实查询，避免幻觉。

### 3. 为什么使用 RAG？
企业制度、操作规范和流程文件不能让模型自由发挥。RAG 让模型基于真实文档回答，并且能给出引用。

### 4. RAG 如何优化？
我一般会从这几个方向讲：
- 分块策略
- 检索召回
- Rerank 精排
- Query 改写
- 元数据保留
- PDF/表格解析增强

### 5. 如何防止幻觉？
- 业务数据来自数据库
- 制度数据来自 RAG
- Tool 结果回传模型
- 不确定时拒答
- 回答要求带引用

### 6. 如何处理 Prompt Injection？
我会强调系统 Prompt 优先级高于检索内容，检索内容只作为不可信上下文，工具执行走后端校验，AI 不直接执行业务动作。

### 7. MCP 为什么存在？
MCP 是一种标准化暴露工具和上下文的协议。它比传统 Function Calling 更适合平台化，能让不同客户端统一调用内部能力。

### 8. Tool 如何设计？
我会讲四点：
- 明确 schema
- 参数校验
- 权限控制
- 真实数据库执行

### 9. Memory 如何设计？
我会强调短期 + 长期两层：
- 短期：最近会话、任务上下文
- 长期：用户偏好、历史摘要

### 10. Trace 有什么用？
Trace 用于回答“AI 到底做了什么”。它能记录调了哪些工具、花了多少 Token、延迟多少、是否失败，是系统可审计性的关键。

### 11. Evaluation 怎么做？
我会讲先准备 dataset，再统计：
- Tool Accuracy
- Argument Accuracy
- Retrieval Recall
- Task Success Rate
- Latency
- Token/Cost

### 12. 如果模型挂了怎么办？
我会讲：
- Retry
- Fallback Model
- Graceful Degradation
- Trace 记录失败

### 13. 如果 Tool 调用失败怎么办？
我会讲：
- 返回结构化错误
- Agent 可重试或换路径
- 最终降级为提示性回答
- Trace 记录失败原因

### 14. 为什么不用一个大 Prompt？
因为可维护性、稳定性、审计能力和准确性都会下降。真正企业系统需要分层：Agent、Tool、RAG、Trace。

### 15. 你这个项目最大的亮点是什么？
我建议统一讲成一句话：

> 这个项目不是在演示 AI 能说话，而是在演示 AI 如何在企业系统里可控地做事。

## 四、Demo 讲法建议

### 推荐演示顺序
1. 登录
2. 查询库存 / 订单
3. 查询订单延期风险
4. 问知识库问题
5. 展示右侧 Trace / Tool / Citation
6. 展示 Evaluation 输出

### 讲解时的关键强调
- 数据来自数据库
- 知识来自知识库
- AI 只做决策
- Trace 可审计
- Evaluation 可量化

## 五、面试官可能追问的难点

### 追问 1：RAG 召回不准怎么办？
答：优化分块、增强元数据、引入 Rerank、Query 改写、反馈闭环。

### 追问 2：如何保证答案一致？
答：限制模型自由度、依赖工具、固定 Prompt 结构、记录 Trace、建立评测集回归。

### 追问 3：为什么不直接接 ERP？
答：MVP 阶段先用结构化样例数据，架构上已预留真实系统接入路径。

### 追问 4：如何扩展多用户权限？
答：当前已有 ADMIN/USER，后续可扩展角色、工具白名单、数据范围权限。

### 追问 5：为什么不直接依赖 Agent 框架？
答：我希望把 Agent 流程讲清楚，而不是把核心逻辑藏进黑盒。框架可以作为可选层，但主链路必须可控。
