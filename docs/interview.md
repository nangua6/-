# 面试讲解文档

## 1. 一分钟项目介绍
这是一个制造业企业 AI Agent 平台，用户可以用自然语言查询库存、订单、生产进度、采购信息，并结合企业知识库完成制度问答和风险分析。项目重点不是做一个聊天机器人，而是实现一个真实可审计的 Agent 系统：LLM 负责理解与决策，数据库和知识库负责事实。

## 2. 五分钟项目介绍
项目分为业务系统、Agent 系统、RAG 系统、评测系统和可观测系统。业务系统基于 PostgreSQL 提供真实库存、订单、生产、采购数据；Agent 系统负责理解问题、选择工具、编排执行；RAG 系统负责文档解析、分块、Embedding、检索、Rerank 和引用溯源；评测系统用于验证工具准确性、检索命中率和任务成功率；可观测系统记录 trace、tool、token、cost 等运行指标。

## 3. 项目架构解释
前端通过 API 请求后端，后端通过 Session/Memory 管理上下文，Agent 负责任务理解与工具调用，RAG 负责知识检索，所有事实数据来自 PostgreSQL，AI 只做决策层。

## 4. 为什么使用 Agent？
因为真实业务问题往往不是单次查询就能解决。例如“SO20260001 为什么可能延期”需要同时查询订单、生产进度和库存，并结合业务规则计算风险。Agent 能把复杂任务拆成多步执行。

## 5. 为什么使用 Function Calling？
Function Calling 让模型输出结构化工具调用，而不是自由文本猜测。这样后端可以真实执行业务查询，避免幻觉。

## 6. 为什么使用 RAG？
因为企业制度、流程和规范不能让模型自由发挥。RAG 让模型基于真实文档回答，并支持引用溯源。

## 7. RAG 如何优化？
可以从文档分块策略、Embedding 质量、Top-K、Rerank、Query 改写、重叠切分、PDF 表格解析、元数据保留等方面持续优化。

## 8. 如何防止幻觉？
- 业务数据来自数据库
- 知识问答来自 RAG
- 工具结果回传模型
- 不确定时拒绝回答
- 回答要求带引用

## 9. 如何处理 Prompt Injection？
- 检索内容视为不可信上下文
- 系统 Prompt 优先级高于检索内容
- 工具执行走后端校验
- 不允许模型直接执行业务动作

## 10. MCP 为什么存在？
MCP 提供一种标准化方式暴露工具、资源和上下文，适合企业平台化场景，让不同 Agent、IDE 或外部系统统一调用内部能力。

## 11. 如何设计 Tool？
Tool 必须具备：
- 明确 Schema
- 参数校验
- 权限控制
- 真实数据访问
- 错误处理
- 可观测日志

## 12. 如何设计 Memory？
采用短期 + 长期两层：
- 短期：最近会话和上下文
- 长期：用户偏好、历史摘要、重要业务上下文

## 13. 如何做 Evaluation？
准备 dataset，按类型覆盖：
- 简单查询
- 多轮对话
- Tool Calling
- RAG
- 组合任务
- 边界问题

然后统计：
- Tool Accuracy
- Argument Accuracy
- Retrieval Recall
- Task Success Rate
- Latency
- Token/Cost

## 14. 如何优化 Latency？
- 缓存
- 更小模型
- 精简上下文
- 改善检索质量
- 减少无效 Tool 循环
- 流式响应

## 15. 如何降低 Token Cost？
- 上下文压缩
- 摘要历史
- RAG 精排
- Tool schema 精简
- 分级路由模型

## 16. 如果模型挂掉怎么办？
- Retry
- Fallback Model
- Graceful Degradation
- 前端提示系统异常

## 17. 如果 Tool 调用失败怎么办？
- 返回结构化错误
- 重试或换路径
- Agent 降级回答
- Trace 记录失败原因

## 18. 为什么不用一个大 Prompt 解决所有问题？
因为可维护性、稳定性、审计能力和准确性都会下降。拆成 Agent + Tool + RAG 更贴近真实企业系统。

## 19. 如何保证 AI 不越权？
- 权限校验
- Tool 白名单
- 数据隔离
- 敏感操作由后端执行
- AI 只负责决策，不直接执行

## 20. 这个项目下一步怎么扩展？
- 更完整的 Evaluation pipeline
- 更强 RAG（表格/图片解析）
- Streaming
- 更细权限体系
- 真实 MCP 资源暴露
- 更完整前端 Trace 面板
- 多模型路由策略
